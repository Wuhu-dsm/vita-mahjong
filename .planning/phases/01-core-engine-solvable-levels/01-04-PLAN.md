<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User touch input → GameEngine | Untrusted pointer coordinates cross into game logic. |
| Level JSON → Renderer | Loaded level data drives sprite creation and must be validated. |
| Asset files → Renderer | Loaded textures and CSS are consumed by PixiJS/browser. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | npm/pip package installs | high | mitigate | No new runtime packages are added; reuse packages from Plan 01-01 that passed the 01-RESEARCH.md legitimacy audit. |
| T-01-SC | Tampering | npm/pip package legitimacy checkpoint | high | mitigate | If any additional rendering utility is installed, verify it against the audit or pause for human approval. Current plan adds no new packages. |
| T-01-02 | Tampering | Loaded level JSON at runtime | medium | mitigate | GameScreen validates the loaded JSON schema (id number, stones array, even face counts, maxLayer ≤7) before constructing BoardModel; malformed data is rejected and the level fails to load. |
| T-01-03 | Denial of Service | Renderer / game loop | medium | mitigate | Object pool caps active tile nodes; board size is capped at 128 tiles; animations use delta-time so slow devices degrade gracefully rather than soft-locking. |
| T-01-05 | Spoofing | Pointer tap spoofing | low | accept | Local single-player game; spoofed taps cannot affect other users. Accept and rely on PixiJS event validation. |
| T-01-08 | Tampering | Loaded texture/font files | low | mitigate | Use only assets generated by committed scripts or referenced from the asset manifest; do not load user-supplied URLs. |
</threat_model>
