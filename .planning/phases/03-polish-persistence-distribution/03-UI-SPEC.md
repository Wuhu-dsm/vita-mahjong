# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Rendering note:** Vita Mahjong uses PixiJS 8 canvas rendering, not DOM. All spacing, typography, and color values are pixel-accurate PixiJS primitives within a 1080×2400 design canvas.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (PixiJS 8 canvas, no DOM component library) |
| Preset | not applicable |

## Color

Established palette from `config.ts` lines 19-29 (source: Phase 2, carried forward):

| Role | Value | Usage |
|------|-------|-------|
| Dominant — Home (60%) | `0x7A4F2E` (#7A4F2E warm brown) | Home screen background |
| Dominant — Game (60%) | `0x1B4D3E` (#1B4D3E dark green) | Game screen background |
| Dominant — Result (60%) | `0x0F172A` (#0F172A dark blue) | Result screen background |
| Secondary (30%) | `0xD4A574` (#D4A574 tan/gold) | Labels, icons, footer text; about 30% of non-background surfaces |
| Accent (10%) | `0xF5D78E` (#F5D78E warm gold) | Screen titles, button strokes, tray border, score floaters, progress indicators |
| Destructive | `0xC0392B` (#C0392B red) | Destructive actions only (reset confirmation heading stroke, confirm button stroke) |
| Card surface | `0x3E2723` (#3E2723 dark brown) at 0.6 alpha | Settings row cards, info panels |

**Accent reserved for:** screen titles, text strokes on primary buttons, active indicators (mute on), tray border, score floater text, and the particle burst primary color. Accent is NOT used for: body text labels, secondary buttons, passive backgrounds, or non-interactive elements.

**Particle burst palette** (Phase 3 new — source: CONTEXT.md D-05):
| Element | Color | Rationale |
|---------|-------|-----------|
| Primary particle | `0xF5D78E` (accent gold) | Match the established accent; warm, celebratory |
| Secondary particles | `0xFF6B6B` (soft red), `0x4ECDC4` (teal), `0xFFE66D` (light gold) | Themed variants drawn from tile-face accent colors |
| Low-end fallback | `0xF5D78E` only | Single color, fewer particles (8-10 vs 15-20) |

Note: PRD §11.3 describes white particles (#F8F8F8); CONTEXT.md D-05 overrides with themed colors matching tile faces. The contract follows CONTEXT.md as the authoritative Phase 3 decision document.

## Copywriting Contract

Phase 3 introduces one new UI interaction: the Reset Progress flow. All existing copywriting from Phases 1–2 carries forward unchanged.

| Element | Copy | Context |
|---------|------|---------|
| Reset Progress CTA | `重置进度` | Settings screen button label (source: CONTEXT.md D-04) |
| Confirmation heading | `确认重置` | Popup title when user taps "重置进度" |
| Confirmation body | `确定要重置进度吗？所有关卡记录将被清除。` | Popup description (source: CONTEXT.md specifics) |
| Confirmation cancel | `取消` | Dismiss without action (source: CONTEXT.md specifics) |
| Confirmation confirm | `确认重置` | Execute reset → clears localStorage currentLevel to 1, dismiss popup (source: CONTEXT.md specifics) |
| Post-reset feedback | (none — no toast; home screen level button silently updates to "关卡 1") | On next return to home screen |
| Empty state | Not applicable | Phase 3 adds no new empty states |
| Error state | `存储空间不足，无法保存进度。` | localStorage write failure (quota exceeded). Fallback: game continues in-memory without persistence for current session. No retry UI — silently degrade. |

**Destructive actions in Phase 3:**

| Action | Confirmation Approach | Severity |
|--------|----------------------|----------|
| Reset Progress | Modal overlay with explicit body text and two-button choice (cancel / confirm). Cancel is default-safe (no action). Confirm button uses destructive styling (red stroke). | High — clears all progress irreversibly |

## Interaction States & Animations

### Settings Screen: Reset Progress Flow

```
[Settings Screen] → User taps "重置进度" button
  → ConfirmationDialog appears (overlay + panel, scale-in 200ms)
  → User taps "取消" → dialog dismisses, no change
  → User taps "确认重置" → localStorage cleared, currentLevel = 1
    → dialog dismisses → home button label set to "关卡 1"
    → SettingsScreen remains visible
```

### Match Elimination: Particle Burst

```
[GameScreen] → Two matching tiles removed from board
  → ParticleBurst.show(midX, midY) — spawn 15-20 particles at midpoint
  → Each particle: radial velocity (random angle, 80-200px/s), gravity (300px/s²), fade out (0→1 alpha over 500ms)
  → Low-end (detected via frame sampling): 8-10 particles, no gravity, simpler fade
  → Animation completes → particles returned to pool
```

### PWA Install Flow

```
[Browser] → User visits deployed URL
  → Browser detects manifest.json + SW registration
  → "Add to Home Screen" prompt (native browser behavior)
  → Installed PWA opens in standalone mode, portrait locked
  → Offline: Service Worker serves cached assets (home screen, levels 1-20, textures)
```
