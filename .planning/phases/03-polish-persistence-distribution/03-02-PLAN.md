    === PARTICLEBURST.TS (NEW) ===

    Create src/renderer/effects/ParticleBurst.ts extending Container. Follows the ScoreFloater show/update pattern + TilePool object pool pattern. Uses PixiJS 8 Graphics API per RESEARCH.md (NOT @pixi/particle-container — removed in v8).

    INTERNAL ParticlePool (follow TilePool pattern from TilePool.ts lines 8-48):
    - BUDGET = 40 (static, per RESEARCH.md A3: worst-case burst overlap)
    - idle: Graphics[] (available for reuse)
    - active: Set&lt;Graphics&gt; (currently in-flight)
    - allocated: number (total created, cap at BUDGET)
    - obtain(parent: Container): Graphics | null — pop from idle or create new Graphics if under budget; add to active set; parent.addChild; set visible=true/alpha=1; clear() previous drawings
    - free(g: Graphics): void — remove from active set; parent.removeChild; set visible=false; clear(); push to idle

    Particle data structure per burst instance (not a class — inline objects):
    ```
    { graphic: Graphics, vx: number, vy: number, elapsedMs: number }
    ```

    CONSTRUCTOR:
    ```
    constructor(isLowEnd: boolean)
    ```
    - super()
    - Store isLowEnd flag
    - Store particleCount: isLowEnd ? config.particles.lowCount : config.particles.highCount (per D-07)
    - Create ParticlePool instance
    - Set visible = false (Container extension pattern)

    METHOD: emit(midX: number, midY: number): void
    - Per D-05: particle style = match burst, scattering from midpoint between matched tile positions
    - Per D-06: called ONLY for match elimination (integration in GameScreen handles this)
    - Obtain N particles from pool (N = this.particleCount)
    - If pool returns null (exhausted), skip silently — no crash, just a dropped burst per RESEARCH.md A3
    - For each particle:
      - Angle: random 0 to 2π (circular scatter per CONTEXT.md specifics)
      - Speed: random between config.particles.minSpeed and maxSpeed * 60 (scale for per-frame delta)
      - vx = Math.cos(angle) * speed, vy = Math.sin(angle) * speed
      - Draw: rect(-size/2, -size/2, size, size) filled with random color from config.particles.colors (primary 60% probability, random secondary 40% split)
      - Position at (midX, midY)
      - Push to internal active array
    - Set this.visible = true

    METHOD: update(ticker: Ticker): void
    - Called from GameScreen.tick(), same pattern as scoreFloater.update(ticker) (line 96)
    - If !this.visible, return early
    - Track anyActive = false
    - For each active particle (iterate backward for safe removal):
      - elapsedMs += ticker.deltaMS
      - progress = Math.min(elapsedMs / config.particles.burstDurationMs, 1) — per UI-SPEC: ~500ms burst
      - Update position: graphic.x += vx * ticker.deltaMS * 0.06 (velocity scaling per RESEARCH.md)
      - Update position: graphic.y += vy * ticker.deltaMS * 0.06
      - vy += config.particles.gravity (downward pull, gravity effect per UI-SPEC)
      - graphic.alpha = 1 - progress (fade out)
      - graphic.scale.set(1 - progress * 0.6) (shrink)
      - If progress >= 1: pool.free(graphic); remove from active array
      - Else: anyActive = true
    - If active array is empty: this.visible = false (hide container when idle)

    ```
    import { VitePWA } from 'vite-plugin-pwa';

    export default defineConfig({

      publicDir: 'public',
      plugins: [
        VitePWA({
          registerType: 'autoUpdate',
          manifest: {
            name: 'Vita Mahjong',

            description: '经典麻将连连看 - 放松消除体验',

              { src: 'icons/icon-512.png', sizes: '512x512', type: 'image/png' },
            ],
          },
          workbox: {
            globPatterns: ['**/*.{js,css,html,json,png,svg,woff2}'],
            runtimeCaching: [
              {
                urlPattern: /^\/levels\/.*\.json$/,
                handler: 'CacheFirst',
                options: {
                  cacheName: 'level-data',
                  expiration: { maxEntries: 25 },
                },
              },
            ],
          },
        }),
      ],
      build: {
        outDir: 'dist',
        sourcemap: true,
      },
      server: {
        host: '127.0.0.1',
        port: 5173,
      },
      test: {
        globals: true,
        environment: 'node',
      },
    });
    ```

    KEY CONFIG DECISIONS (per D-09, RESEARCH.md, and RESEARCH.md "Common Pitfalls"):

    1. registerType: 'autoUpdate' — automatically updates SW when new build is deployed; no user prompt needed
    2. manifest.display: 'standalone' — full-screen PWA without browser chrome
    3. manifest.orientation: 'portrait' — mobile portrait only, per project constraints
    4. manifest.theme_color / background_color: '#7A4F2E' — matches config.colors.homeBg (warm brown)
    5. workbox.globPatterns: pre-caches all js/css/html/json/png/svg/woff2 files in the build output
    6. runtimeCaching for levels: CacheFirst for /levels/*.json (level data is versioned with the build — per RESEARCH.md pitfall 3: CacheFirst is safe for content that changes with deployments). maxEntries: 25 covers all 20 levels + headroom.
    7. No explicit CacheFirst for static assets — they're covered by globPatterns precache (generateSW auto-precaches matched globs)
    8. No explicit NetworkFirst for index.html — Workbox generateSW automatically handles navigation requests with NetworkFirst by default for the entry point

    Per D-09: basic PWA with manifest + Service Worker caching static assets and level JSON. "Add to Home Screen" supported.
